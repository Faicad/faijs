# Agent Note: occt-wasm upgrade 3.8.4 → 5.6.0 with imprint parity gap

Status: implemented

English | [中文](2026-10-05-occt-wasm-upgrade-3-8-to-5-6-implemented.zh.md)

## Problem

`occt-wasm` was pinned to `3.8.4`. Upgrading to `5.6.0` is necessary to pull the
kernel closer to current OCCT (the `desc`/`partNumber` XCAF enrichment kept
failing to *find* the fields as well — see the gap note). Because this dependency
is the sole OCCT boolean/general-fuse surface for the BREP chain, the upgrade is
an API-shape and behavior change that must be verified commit-wide before it can
land.

## Decision

Upgrade the workspace to a single installed `occt-wasm@5.6.0`.

- The root `package.json` pins `overrides: { "occt-wasm": "5.6.0" }` (exact, no
  caret). Every per-package range was bumped to `^5.6.0` (`core` peer,
  `cq-compat-compare`, `faijs-cadquery`, `faijs-fasteners`, `faijs-gears`,
  `faijs-sketch`, `faijs-viewer` deps + dev, `faijs-freecad` dev, and the `demo`
  CDN `importmap` + wasm URLs hand-synced to `5.6.0`).
- `package-lock.json` was regenerated by **deleting the lock and reinstalling**
  (a stale lock otherwise kept `node_modules/occt-wasm` at `3.8.4` in spite of the
  updated ranges). `npm ls occt-wasm` confirms one `5.6.0` instance.
- The **only** type-level break was `getBoundingBox`: the new API keeps the base
  `(shape, useTriangulation: boolean)` overload while adding an options overload,
  so `occt-primitives.ts` now calls it with `useBounding ?? false`.
- The `getBoundingBox` fix plus the version bump is declared as a **declaration
  consistency** change, not a lockstep bump — occt-wasm is a third-party dep and
  is exempt from `check-lockstep`.

## Behavioral deltas recorded in tests

- `fillet` on an already-filleted output **now succeeds** (5.6.0 fixed the
  Re-fillet/`TopoDS::Solid·Fail` block). The old `p1-workplane-ops.test.ts` GOTCHA
  pinned the rejection; it was updated to assert the re-fillet resolves and yields
  a strictly smaller solid.
- `imprint` (mapped to `fuseAll` / `BRepAlgoAPI_Fuse`) now **Glues** two
  face-touching solids into **one solid** (was two on 3.8.4). The volume is
  unchanged; the solids/face count deviates from CadQuery 2.8.0 (whose `imprint`
  maps to `BOPAlgo_Builder` keep-cells). The test expectations were updated to the
  5.6.0 result (1 solid, 10 faces for `b1,b2`; 1 solid, 11 faces for the partial
  touch `b1,b3`).

## Alternatives considered

- **Preserve CadQuery `imprint` parity (keep two touching solids)** — the user's
  first choice, but **not implementable on the 5.6.0 JS surface**: 5.6.0 exposes
  only `fuseAll`/`booleanOp` (Fuse/Cut/Common), `split` (`BOPAlgo_Splitter`),
  `intersectionCells` (`BOPAlgo_CellsBuilder`), and `unifySameDomain`; there is **no
  `BOPAlgo_Builder` keep-cells (general-fuse) primitive**. Reproducing the
  2-solid-+ one-face result would require an upstream occt-wasm binding or a
  fragile JS approximation. Per user decision this is **recorded as a gap, not
  implemented**; the parity deviation is documented in the test and the
  `workplane.ts` JSDoc.
- **Keep `3.8.4`**: rejected — the whole point of the upgrade is to move off the
  stale OCCT and toward the current kernel.
- **Reset root `overrides` to `^5.6.0`**: rejected (the exact pin is simpler and
  works; removed).

## Consequences

- All `core` (225 files / 3003 tests), `faijs-tests` (55 files / 588), and
  `faijs-cadquery` (598) test suites pass clean with no stderr.
- `faijs-freecad` has one failing `sketch-empty-geoms` test that is **not
  upgrade-related**: it depends on the external fixture
  `D:/Faicad/FreeCAD-library/Electrical Parts/Endstop/endstop-v1-2-makerbot.fcstd`,
  which is absent on this machine. It fails regardless of the occt-wasm version.
- The `imprint` solids-merging parity deviation is a **known gap** — an upstream
  `occt-wasm` `BOPAlgo_Builder`(keep-cells) binding would restore CadQuery 2.8.0
  parity, and is not wired this round.
