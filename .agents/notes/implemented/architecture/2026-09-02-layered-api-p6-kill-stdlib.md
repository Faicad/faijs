# Agent Note: Layered API port — P6 L3 full surface and stdlib retirement

Status: implemented

English | [中文](2026-09-02-layered-api-p6-kill-stdlib.zh.md)

## Problem

The `@faicad/faijs-stdlib` package stood outside the L0–L3 layering defined by the architecture plan: its ~30 `cad.*` ops lived in a second package with its own `./stdlib` subpath, so the root facade re-exported them through a parallel entry while the engine internals lived in `packages/core`. The plan's D1 decision ("cancel the stdlib package and the standard-library concept") followed the user's judgment: stdlib was "not a standard library, just the API set that props up 3d_editor", so it had no generic-purpose value and could not serve as the L3 API surface. P6's gate was L3 full: every public op settles into `packages/core/src/api/` (the L3 API face), the package is deleted, and the "标准库"/"stdlib" placeholder term gives way to **faijs API 面** throughout docs and messages.

## Decision

1. **Relocate the library face into core — no second package.** All of `packages/stdlib/src/*` moves into `packages/core/src/api/` (ops + `brepjs-mirror/` + `internal/` + the `index.ts` barrel). Cross-references inside core are rewritten to relative imports (`../…`, `../../…`); `packages/stdlib/` is deleted from the workspace, root `package.json` (workspaces, deps, `build` script, `lint` scope), tsconfig paths, vitest alias, mech-lib peer deps, and the lockfile. `packages/core/package.json` exports `./api`, `./api/*` and drops the `./stdlib` / `./stdlib/*` subpaths.
2. **Rename the namespace in place of "internal stdlib".** `internal-stdlib.ts` becomes `api-namespace.ts`; the factory symbol `createInternalStdlib()` becomes `createApiNamespace()`. The word "stdlib" is removed from the code-facing surface. The root facade's `createRuntime` wrapper injects the library via `registerLib('cad', createApiNamespace())` instead of the stdlib barrel; `src/browser.ts` does the same for the browser (no-node) surface. `packages/core` `index.ts` and `browser.ts` close with `export * from './api'` plus `export { createApiNamespace }`, so the L3 API face is part of the core entry.
3. **Merge the concept into the docs.** `docs/api-contract.md` (and `.zh.md`), the README import tables, `AGENTS.md`, and `docs/ops-api-inventory.md` (regenerated by `gen-ops-api-inventory.ts` from the L3 declarations) now call the face the **faijs API namespace**. The root facade subpath count drops from 11 to 10.
4. **Host migration precedes the deletion (D1-⓪).** 3d_editor's two production imports of `@faicad/faijs/stdlib` (`LiveDrillPreview.tsx` for `drill`, `EngravingCore.ts` for `engrave`) were repointed to `@faicad/faijs/browser`, the `drill`/`engrave` heads added to the A/B/C/D whitelist lock in `contract-entry.test.ts`, the test mock that referenced the dead module repointed, and the host reinstalled from freshly packed tarballs. The string `stdlib` no longer appears anywhere in the host tree.

## Alternatives considered

- **Keep the package and re-export it from core.** Rejected: it would leave a parallel package whose existence the plan's D1 explicitly ends, and a second package re-introduces the ghost-dependency and version-coupling overhead the workspace consolidation removes.
- **Keep the `createInternalStdlib()` name.** Rejected: "internal stdlib" describes a package that no longer exists; `createApiNamespace()` states what the thing is (the L3 API namespace), and the rename is the plan's explicit rename step.
- **Redefine the API ops from scratch on core primitives instead of relocating the existing implementations.** Rejected: P5's vendored L2 layer plus the existing `defineOp` dual-link implementations already cover these ops and pass brepjs's own suites; a from-scratch redo would discard a green baseline without adding capability. The implementations move with only their home and base imports changed.
- **Delete `assert.ts` and `geom.ts` in this commit.** Rejected: their replacement (L3 `schema` declarations; brepjs `measurement/query`) is deferred by the plan, so deleting them now would break the still-referencing surface. They move along with the rest.
- **Drop the `brepjs-mirror/` files (threadFns/joinery-brep).** Rejected: they are the existing portable-sample of the D11 adapter pattern (kernel direct calls, manual release, Result→throw boundary) and the plan says to keep them — they move to `api/brepjs-mirror/` with unchanged relative `../../occt-kernel` references.

## Consequences

- The delivered repo is now "engine + L3 API face, both in `packages/core`"; the root facade re-exports 10 subpaths, `@faicad/faijs-stdlib` is gone, and the two-package mental model collapses into one.
- Guards stay green after the move: workspace tests (core 926 passed / 9 skipped, tests 1269 passed / 2 skipped, mech-lib 23 passed), root + per-workspace `typecheck`, `lint` 0 errors, `check-ghost-deps` (488 files), `check-workspaces-order`, `npm run build` (core, then root), `check-layer-boundaries` (237 P3/P5 vendored files), vendored strict `tsc`, `api-surface-snapshot.mjs` (10 subpaths), and `doc-sync` (13 gates). The only known red flag is the pre-existing circular dependency inside the `vendored/brepjs` P3/P5 tree — it is third-party vendored code and predates this commit; the layer/ghost/typecheck gates that matter all pass.
- The browser/no-node host gets the same API face via `/browser`; a breakdown that would break the drill/engrave host path now surfaces in the host's own contract test and typecheck before it ships.
- Tarballs: `npm pack` at root and at `packages/core` re-emit fresh `faicad-faijs-0.7.4.tgz` / `faicad-faijs-core-0.7.4.tgz` with no `./stdlib` export and no `dist/stdlib`; the 3d_editor re-install pulls the new tarballs. The stale `packages/core/dist/stdlib/*` remnant (88 files, git-ignored, untracked) stays ignored and never ships in a package.
