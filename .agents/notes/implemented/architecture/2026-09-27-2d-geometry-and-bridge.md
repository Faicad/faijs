# Agent Note: pure-2D geometry port and unified placement pipeline

Status: implemented

English | [中文](2026-09-27-2d-geometry-and-bridge.zh.md)

## Problem

faijs had no pure, kernel-free 2D geometry layer. `cad.profile` built 3D edges directly from 2D segment data by bypassing geometry (`profile.ts` loop-to-wire), with its own ad-hoc hole classification (parent chain + `depthOf` + area comparison). The 2D→3D bridge primitives the plan needs (`sketchOnPlane`/`sketchOnFace`/`punchHole`) had zero implementation, and the kernel contract (`BrepEngineApi`) does not expose any curve-handle system. Growing the 3D moulding story on this base would mean duplicating 2D geometry logic in the api layer.

## Decision

core gains a kernel-independent pure-2D geometry base under `packages/core/src/geometry2d/`, ported from brepjs (Apache-2.0, attribution in file headers):

- `curve2d.ts` — the `Curve2dObj` family (line / circle / ellipse / bezier / bspline / trimmed), evaluate / tangent / bounds, constructors, transforms, serialization, `intersectCurves2dFn`, `CurveBBox2d` / `createCurveBBox2d`; the brepjs `__bk2d` discriminant is renamed `kind2d` (and `__bk2d_bbox` → `kind2d_b`) to faijs-style names.
- `bbox2d.ts` — pure-data `BBox2d` helpers.
- `blueprint.ts` / `compound-blueprint.ts` / `blueprints.ts` — `Blueprint` / `CompoundBlueprint` / `Blueprints` as pure object containers (no kernel handles, no `dispose()`).
- `organise.ts` — `organiseBlueprints` classification (`bbox`-overlap grouping + `isInside` nesting probe via `intersectCurves2dFn`).
- `adapt.ts` — structural adapter from the legacy `cad.profile` segment shape (line / arc) to `Curve2dObj`, preserving `ccw` direction and full circles.

`cad.profile` (F2) consumes this unified pipeline: `buildProfileShape` now converts each contour to a `Blueprint` and runs `organiseBlueprints`, then builds 3D line/arc/bezier edges from the classified curves. The old ad-hoc parent-chain / `depthOf` / area-comparison classification is deleted.

2D→3D bridging (`geometry2d/bridge/`) is the same base's placement step later — per plan the bridge keeps alive the occt-only primitives (`liftCurve2dToPlane` / `draftPrism`) on the occt platform surface and combination at composition time.

Nested-loop semantic is a decision, not an accident: nested loop = hole, disjoint loop = independent island, odd depth = hole, even depth = island again. `organiseBlueprints` reproduces this, also enforced as parity by the migrated profile regression tests. `ccw` is a geometric-direction field, not metadata: the adapter derives arc sweep per-direction (CW forward sweep = `startAngle − endAngle`) and keeps full circles as real `circle` curves (the 3-point construction degenerates through the singular start/end point).

`organiseBlueprints` replaces brepjs's Flatbush spatial index with a pure union-find over `bbox`-overlap — no Flatbush dependency, pure TS, no kernel handle. The wire assembly for planar faces reuses `makeWire` and rebuilds real arc edges from three on-arc points (`makeArcEdge`), bezier via `makeBezierEdge`; sampled polylines are used only for non-analytic curves (ellipse / bspline).

## Alternatives considered

- **Port Flatbush in as a core dependency.** Rejected: heavier than needed; the same classification is reachable with a pure bbox-overlap union-find that the migrated tests already pin, and any future change is local to `organise.ts`.
- **Keep `cad.profile`'s old parent-chain classification.** Rejected: it is ad-hoc and does not generalize to arbitrary `Curve2dObj`-based inputs (`cad.draw` / sketch) that must share the same pipe.
- **Build the full bridge SKU in this round.** Rejected: the placement acceptance needs the pure-2D base to land and be regression-safe first; the bridge is a follow-on on the same base.

## Consequences

- core exposes `@faicad/faijs/geometry2d/*` subpath exports.
- The profile classification lives once, in `organiseBlueprints`, shared by `cad.profile` and later `cad.draw` / sketch-family inputs.
- Full circles, `ccw:false` arcs, and multi-island / hole-in-island contours all pass the migrated tests (33 geometry2d + 5 profile multi-island + the arc GOTCHA guards, plus multi-engine parity `mismatches=0`).
- The pure-2D base is the prerequisite for `geometry2d/bridge/` placement
- `geometry2d/bridge/` (E2) lands the plane-lift composition: `plane.ts` (frame `makePlane`/`namedPlane`/`lift`) and `lift-on-plane.ts` (`liftCurve2dToPlane`/`curvesAsEdgesOnPlane`/`assembleWire`). It types its kernel as `Pick<BrepEngineApi, makeLineEdge|makeArcEdge|makeBezierEdge|makeWire>` so callers pass `getBrepApi()` with no casts; the module imports the kernel contract but never `api/`.
- `cad.sketchOnPlane` (E2+op) lands: same contour-loop input as `cad.profile`, placed on a named or explicit `{origin, normal, xAxis}` plane; `as:'face'`/`'wire'`; registered in the cad namespace + symbol table.
- The pen layer (`BaseSketcher2d`) lives in core `geometry2d/pen-sketcher.ts` for now — the pure-object port of the brepjs sketcher — the interim home for the C-group DSL; the eventual move to `@faicad/faijs-draw` is a mechanical re-home, since the pen and the canned factories only depend on `geometry2d/*`.
- SVG-style elliptical arcs land as `geometry2d/svg-ellipse.ts` (`normalizeEllipseRadii`/`convertSvgEllipseParams`/`makeEllipseArcFromSvgParams`), emitting a `TrimmedCurve2d` over an `Ellipse2d` (parameter = sweep angle). This unblocks `ellipseTo`/`ellipse`/`halfEllipseTo`/`halfEllipse` on the pen.
- C2 lands as `geometry2d/blueprint-sketcher.ts` (`BlueprintSketcher` → `done(): Blueprint`) and `canned-blueprints.ts` (`polysidesBlueprint` / `roundedRectangleBlueprint`, circular + elliptical corners). `BlueprintSketcher` still inherits the base `close(): Curve2dObj[]`; the closed-contour `Blueprint` is obtained by wrapping `new Blueprint(pen.close())`.
- The `@faicad/faijs-draw` package (C3 base) exists: `src/draw.ts` offers the fluent `draw(session)` entry plus a `draw.rectangle`/`draw.roundedRectangle`/`draw.polygon`/`draw.circle` factory namespace over core's `geometry2d`, with `src/drawing-factories.ts`; workspace/tsconfig/vitest-alias and all publish gates (order/lockstep/ghost-deps/export-jsdoc) pass, and `npm run build` emits a clean dist. The script runtime registration of a `cad.draw` symbol is now in place: `src/namespace.ts` exposes `createDrawCadNamespace()` / `mergeDrawNamespace()` (draw merged over core's `createApiNamespace()` platform surface) and `registerDrawSymbols()` / `unregisterDrawSymbols()` (toggle the `draw` key in the core symbol table), so a host folds it in via `rt.registerLib('cad', createDrawCadNamespace(), { default: true })`.
- The shared placement core is extracted as `buildShapeFromBlueprints(kernel, plane, blueprints, as)` in `core/api/sketch-on-plane.ts`, and `buildSketchOnPlaneWith` now converts `ProfileLoop[] → Blueprint[]` then calls it. The placement helper must stay in `api/` (it returns a `Shape` and imports `fromBrep`/`solidToShape`); the `geometry2d/bridge` modules are forbidden from importing `api/`. A core e2e proves the draw-package contour shape (a `roundedRectangleBlueprint` `Blueprint`) placed via `buildShapeFromBlueprints` and kernel-`extrude`d yields a positive-volume solid — the F6 "draw entrance → shared placement → extrude" seam.
- C4 projection lands in the draw package (`src/projection.ts`): `projectPointToPlane`/`projectWire`/`drawFaceOutline`/`drawProjection` project 3D wires onto a plane frame (named plane or explicit frame) into a plotted `Blueprint`. The projection is the strict inverse of core bridge `liftPointToPlane` (`(p−o)·xDir/(p−o)·yDir` on the orthonormal frame), is kernel-free, and imports core `geometry2d` only (plane frame from `@faicad/faijs/geometry2d/bridge/plane`). A roundtrip test pins the inverse-equivalence GOTCHA; an XZ-frame test documents that a wire lying flat in the XY plane projects flat on the XZ frame (2D y is the frame's y, i.e. world Z for wires that actually live there).
- The draw primitive factory set is complete and reachable both as named exports and as `draw.xxx` namespace members: `rectangle`, `roundedRectangle`, `polygon`, `circle`, and `ellipse` (a full CCW `makeEllipse2d` single-curve contour exposing center/radii/rotation). The ellipse contour destructures into a sampled polyline at placement time, mirroring the `circle` single-contour path.
- A precise `parameterOfPoint(c, px, py, maxRatio=0.1)` lands in core `geometry2d/curve2d` (exposed at `@faicad/faijs/geometry2d`): an N=80 coarse grid refined by Newton onto the perpendicular foot `(curve−P)·tangent=0`, returning `null` past a geometric-extent ratio guard. On a radius-5 circle it converges to ~1e-9 (versus ~0.06 for the raw grid), which is the hook D1/D3 (2D boolean / corner / offset work) was waiting for; the standalone `refineParam` kept its original 80-sample behavior.
- Two sub-curve primitives complete the D-group basis layer: `trimCurve(c, tStart, tEnd)` builds a `TrimmedCurve2d` over a native-domain parameter range (reusing the unwrapped basis), and `splitCurveAt(c, t)` cuts one curve at an interior native-domain parameter into two trimming sub-curves (`null` when `t` is not interior). Together with `parameterOfPoint` and `intersectCurves2dFn` these are the low-level cut/splice ops D1 2D-booleans and D3 fillet/chamfer need, all pure and exposed at `@faicad/faijs/geometry2d`.
- The D3 corner splice lands in the draw package `src/ops/custom-corners.ts`: `chamfer2d(corner,p,q,inset)` joins two straight segments sharing a vertex with a straight inset edge, and `fillet2d(corner,p,q,radius)` rounds that vertex with a tangent circular arc. The tangent points sit at a common inset (`radius·cot(θ/2)`) on the angle bisector, and the fillet arc is built through the two tangent points plus the corner-side midpoint via `makeArc2dThreePoints`, so its radius is exactly the requested `radius` with no sweep-casing ambiguity. Both return the three boundary curves of the splice (first, corner, second) ready to reassemble into a `Blueprint`. Pure, kernel-free, imports `geometry2d` only. Full-angle coverage (D3): on a sharp corner the tangent reach `radius·cot(θ/2)` can exceed an adjacent edge, so the radius (and chamfer inset) is **clamped** to the largest value that keeps both tangent points on their edges — an acute 10° fillet folds to the segment rim instead of past a vertex, and 0 / negative / oversized inputs clamp without failing. Right/obtuse/reflex corners keep the requested radius on-segment.
- D2 lands a miter offset in `packages/draw/src/ops/offset.ts`: `offsetOutline2d(verts, dist)` offsets each edge of a closed CCW polygon by a constant distance along its outward normal and returns, per vertex, the intersection of its two shifted incident edges (O(n)). Positive `dist` grows outward, negative shrinks; exact on convex contours. A companion `offsetPolygonLoops2d(verts, dist)` pushes the offset through `pruneSelfIntersections` (in `src/ops/polygon2d.ts`), which decomposes the loop at proper transversal self-crossings and keeps the positive-area lobes. A robustness sweep (C-channel, Z/stair, L, keyhole, near-closing cusp, hammer, T, fin across outward and inward offsets incl. past-collapse) pins that every non-collapsed concave offset returns only simple, positive-area lobes and a genuinely collapsed thin contour returns an empty result — so the traditionally-tricky tangential / vertex-collapse flips are handled by the transversal split or degenerate to a correct empty (see `offset-sweep.test.ts`). Exported from `@faicad/faijs-draw`.
- D1's two low-level classifiers land in `packages/draw/src/ops/boolean.ts`: `pointInContour(p, pts)` classifies a point with the even-odd horizontal-ray cast, and `segmentIntersection(a1,a2,b1,b2,eps)` returns the crossing point plus the two edge parameters (or `null` for parallel / out-of-range). Boundary contact is numeric (clients snap onto edges explicitly); collinear-overlap returns `null` and is left to the splice stage. Together these decide every "keep-which-side / where-do-they-cross" question the full boolean stitch asks.
- The D1 boolean stitch itself lands in `packages/draw/src/ops/boolean-union.ts`: `booleanUnion2d` / `booleanIntersect2d` / `booleanDifference2d` run the classical split-classify-assemble loop — split each edge of A and B at its crossings with the other polygon (`segmentIntersection`), keep a sub-edge by its midpoint per `pointInContour` (union: not-inside; intersection: inside; difference: A-not-in-B plus the B-boundary inside A read reversed), then walk the kept edges end-to-start into closed loops. Simple (incl. non-convex) polygon inputs yield exact signed areas. A **D1 collinear splice** then lands in the assembly stage (`splice`): it dedupes adjacent points, collapses genuinely-collinear interior vertices (`collinearBetween` drops a middle point that lies on the segment spanned by its neighbours), and drops zero-area degenerate loops — so an edge shared edge-to-edge between two inputs merges into a clean straight run instead of leaving a dangling seam (union of two edge-adjacent squares now returns one correct 4-point rectangle). For `difference`, when A ∩ B has zero area (disjoint or only edge-touching) the result is simply A (an empty-intersection short-circuit) — this avoids the even-odd mis-classification of a shared-seam midpoint as "inside" that previously dropped shared boundary edges.
- D4 SVG roundtrip lands in `packages/draw/src/ops/svg.ts`: `contourToSvgPath(loops)` writes each closed loop as an absolute `M … L … Z` path (3-decimal rounding), and `svgPathToContours(d)` reads the absolute/relative `M`/`L`/`H`/`V` commands (with the implicit line-after-moveto pairs) and `Z` back into loops, supporting integer / decimal / exponent numbers. Exact for polygonal contours, so it round-trips the D-group ops' output.
- GOTCHA (array-frame coords): `.fai.js` plane literals hand the frame as **arrays** (`{origin:[10,0,0],normal:[0,0,1]}`); `toVec3` must normalize the array form. Passing `{x,y,z}` only yields `undefined` coords → NaN wire → occt `makeFace` `CONSTRUCTION_FAILED`.
- E3 `cad.sketchOnFace` lands: the on-surface bridge lives in `geometry2d/bridge/on-surface.ts` — `makeUvMap` (`'original'` identity / `'bounds'`/`'native'` affine-fit onto the face's UV bounds), `curves2dBounds` (samples across each curve's real `curveBounds` domain, **not** `[0,1]`, which under-measures lines spanning `[0,len]` and full circles spanning `[0,2π]`), `buildEdgeOnSurface` (≤2 distinct mapped points → `makeLineEdge`, otherwise `interpolatePoints` spline through sampled on-surface points), and `assembleWireOnFace` (per-Blueprint contour → `makeWire`). The bridges types its kernel as `Pick<BrepEngineApi, pointOnSurface|uvBounds|interpolatePoints|makeLineEdge|makeWire>` and never imports `api/`.
- The `cad.sketchOnFace` op (`api/sketch-on-face.ts`) takes `{ contours, on, face, scaleMode?, as? }`: `face` is a 1-based ordinal or a `cad.faceRef` result, resolved to a live face handle via `brepOf(on)` (ordinal) or `buildEdgeResolutionContext` + `resolveTopoRef` (ref); the classified contours are placed on the host face and `makeFace`-wrapped, or returned as the outer wire when `as:'wire'`. Registered in `createApiNamespace` + `api/index.ts` + regenerated symbol table. The op declares `engines: ['occt']` (surface sampling).
- GOTCHA (on-face UV semantics): occt face UV parameterization is not world-aligned unit scale, so `original` scaleMode is only meaningful when the face's UV equals world xy; the general modes are `bounds`/`native` which affine-fit the contour box onto the face's actual UV bounds. e2e therefore asserts placement + positive-volume extrude rather than exact wire lengths.
- v1 scope: `buildEdgeOnSurface` produces interpolated spline edges that lie on the host face, and `makeFace` on them is exact for planar faces; embedding the placed wire into a genuinely curved host face (`fixWireOnFace`) is a follow-up.
- E4 `cad.punchHole` lands in `api/punch-hole.ts`: `cad.punchHole({contours,on,face,height?,draftAngle?,scaleMode?})` places the contour's samples on the host face, extrudes a prism inward along the face normal (`height`=blind pocket, `height:null`=through), and `kernel.cut`-s it from the solid. Registered in `createApiNamespace` + `api/index.ts` + symbol table; declares `engines: ['occt']`. When `draftAngle > 0` the punch tool is a **tapered frustum**: an occt `loft` between the mouth wire (in the host plane) and an end wire recessed by `height·tan(draftAngle)` toward the contour centre (`h̄` = mean centroid→edge distance), then the same `kernel.cut`.
- GOTCHA (occt extrude volume collapse): the punch rebuilds a **clean, exactly-coplanar** straight-edged polygon in the host face's plane (`buildPolygon3d` projects each sampled point onto the plane through its normal) before extruding. Extruding the on-surface bridge's `wire`-derived face (near-coplanar, z varies by ~1e-7) collapses in OCCT to ~0 volume (bbox fine, `getVolume` ≈ 0.065) — `punch-hole-e2e` pins the corrected on-the-plane volumes.
- GOTCHA (occt pairwise corner join): `ThruSections` `loft` between two same-orientation square wires joints the corners with ruled quad faces, so the measured cut volume is ~2% **above** the clean planar-frustum closed form `(d/3)(A1 + A2 + √(A1·A2))`. The draft e2e therefore asserts the robust invariants (single solid; the tapered cut is strictly **less** than the straight prism's `w·h·d`, and not degenerate) rather than pinning the closed-form value.
- e2e (occt): a 20×20×10 box punched with a centered 4×4 through-slot drops from 4000 to ≈ 3840 as a single solid; a 4×4×4 blind pocket drops to ≈ 3936; a 4×4×4 blind pocket with `draftAngle: 3` cuts strictly less than the straight prism (64) yet stays a single solid (wall taper wired).
