# Agent Note: registry 0.32.3 发布产物缺 solve-tree.js 事故

Status: implemented

[English](2026-10-12-registry-0.32.3-missing-dist-file.md) | 中文

## 问题

`@faicad/faijs@0.32.3` 发布到 registry 的 tarball 中，`dist/api/assembly/solve-tree.js`
**缺失**（同目录的 `solve-tree.d.ts` 存在）。消费方任何
`import … from '@faicad/faijs/api/assembly/solve-tree'`（树模式装配求解，即嵌套成员的
`CqAssembly.solve()` 路径）在导入期直接 `ERR_MODULE_NOT_FOUND` 崩溃。下游
（@faicad/faijs-cadquery parity 测试线）经发布包装配镜像**全军覆没**，装配域只有对本地
打包的 tgz 才能工作。

下游取证链（2026-10-11/12，faijs-cadquery 仓）：

- registry `@faicad/faijs@0.32.3`：`dist/api/assembly/solve-tree.js` **缺失**，`solve-tree.d.ts`
  存在 → 树模式装配求解不可用。
- 同一提交（`edc82fa9`）本地构建打包的 `faicad-faijs-0.32.3.tgz`（`npm run build -w @faicad/faijs`
  加 `npm pack`）：文件**存在**。
- registry `@faicad/faijs@0.32.4` 与 `0.33.2`：文件**存在**；下游全套装配套件 56/56 绿。

缺陷被隔离在 **0.32.3 的 registry 上传物**：源码树没问题、本地 tarball 没问题，只有发布出去
的那份产物不完整。

## 决策

根因定性为**发布产物校验缺口**：发布流程中没有任何环节核对「上传 tarball 的文件清单」与
「workspace 构建产物清单」一致。package.json 的 `files: ["dist", …]` 声明了意图，本地
`npm pack` 也遵守了它，但到达 registry 的产物与本地不一致——没有门禁比对两者。

1. **发布前校验门**：`npm publish` 前将 tarball 文件清单与「新构建的 workspace 包的
   `npm pack --dry-run` 清单」（或存档的 `dist/**` 清单）比对，`dist/**` 中任何本地构建存在
   而上传产物缺失的文件 → 硬失败。成本低（文件清单 diff），恰好覆盖此类事故。
2. **发布后冒烟**：上传后把发布的版本装进临时目录，对一个深层子路径
   （`@faicad/faijs/api/assembly/solve-tree`）做一次导入冒烟 + CLI 冒烟（对 fixture 跑
   `faijs-cli.ts check`）。这是校验门之外的保险带：它验证的是 **registry 那份**，而不是本地那份。

守卫落地前的发行者工作规则：**绝不把本地 pack 当作 registry 副本完整的证据**——直接验证
registry tarball（`npm pack @faicad/faijs@<ver>` + 文件清单 diff，或装上后导入冒烟）。

## 备选方案

- **不处理（0.32.4 已修复）。** 否决：没有任何机制防止复发；该失败模式是静默的（消费方在
  导入期才发现，且很容易错误归因为自己的代码问题——本次实际就发生了，下游为此浪费了一轮
  A/B 归因会话）。
- **归咎 registry/CDN。** 否决：没有传输损坏的证据；更可能的原因是从过期/不完整的 `dist/`
  发布，或在与验证态不同的工作状态下打包。校验门对两种假设都覆盖，无需先确定哪个发生了。
- **改用单体单文件 dist。** 否决：把 dist 打成一个文件会掩盖文件级校验缺口而非修复它，且
  会改变所有子路径导入的消费面。

## 后果

- 0.32.3 是 registry 上的一个坏版本；消费方应钉 `>=0.32.4`。建议对
  `@faicad/faijs@0.32.3` 执行 `npm deprecate`，让工具链主动标记它。
- 发布流程（随守卫改动）新增：发布前 tarball-vs-workspace 文件清单比对、发布后安装导入冒烟；
  不一致则发布失败，而不是发布一份残缺 dist。
- 下游（faijs-cadquery）已在其 parity 计划中留档本事故与取证链；错误归因成本（一轮试图对
  坏 registry 包做 A/B diff 的会话）是发布后冒烟的具体动机。

## 验证

- registry `@faicad/faijs@0.32.3` tarball：`dist/api/assembly/solve-tree.js` 缺失（2026-10-11
  直接安装复现）。
- registry `@faicad/faijs@0.32.4` / `0.33.2`：文件存在；下游装配套件对两者均 56/56 绿。
- 0.32.3 同提交的本地 pack：文件存在——证明缺陷限于 registry 上传物，而非构建本身。
