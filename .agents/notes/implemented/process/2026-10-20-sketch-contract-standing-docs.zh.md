# Agent Note：草图契约落为常设文档；弧度轮廓段面只记录、不转换

Status: implemented

> **已于 2026-10-21 推翻** —— 下面"弧度轮廓段面只记录、不转换"的决定已被撤销：那些槽位不是需要记下来的例外，而是未声明的槽位，即量纲系统上的洞。它们现在声明为 `dim: 'angle'` 并在 op 入口换算。见 `.agents/notes/implemented/architecture/2026-10-21-dimensioned-slots-declared.md`。

[English](2026-10-20-sketch-contract-standing-docs.md) | 中文

## Problem

一次宿主驱动的草图开发暴露出 faijs 的七处文档缺口，全是「重新查一遍要付真实调试成本」的契约事实：脚本面与轮廓段面的角度单位分野、BREP 句柄语义、canonical 椭圆形态、轮廓抽取规则、脚本面单位常量从哪里来、怎么问「哪些 op 能跑在哪个引擎上」、以及驱动度→弧度换算的角度字段登记表。其中两条不只是编辑工作：轮廓段面（`cad.profile` / `cad.sketchOnPlane` / `cad.sketchOnFace` / `cad.sketchOnSurface` 的 `contours[].segments[].startAngle` / `endAngle`）吃的是**裸弧度**，而脚本面其余角度全是度；类型层和量纲校验通道都没有任何东西能让「传了度」失败——它只静默产出错误几何。

## Decision

`docs/sketch-contract.md`（英文／中文／i18n 记录）是草图子系统契约的唯一归属：两条脚本面入口、API × 角度单位表、角度字段登记表、canonical 椭圆、轮廓抽取规则。`docs/api-contract.md` 承载三条引擎边界事实：BREP 句柄语义（§8.6）、脚本面单位常量与量纲校验通道（§15）、平台限定查询面（§7.12）。`docs/library-dev-guide.md` 改为链接这两处，而不是复述。

弧度轮廓段面**按现状记录，不动**。它的单位分野是一个已发布 API 面的事实，不是顺手可以修掉的缺陷；转换它意味着一次改动同时碰 faijs 测试、FCStd 翻译语料与宿主发射层，属于量纲体系统一工作的范围。文档写明这一分野，把两行弧度标为「在量纲系统之外」，并点明后果——不报错，几何悄悄变错。

## Alternatives considered

- **把草图事实放进 `docs/api-contract.md`。** 否决：api-contract 是引擎与运行时契约，塞进整个子系统的细节会让它承担与分派、命名、执行无关的内容；独立的常设文档才能做到一个事实一个家，并让 api-contract 只链接。
- **放进 `docs/ops-api-inventory.md`。** 否决：该文件由 op JSDoc 生成，生成器已停用，手写进去的文字会在生成器下次运行时漂移，且没有任何东西能发现。
- **现在就把轮廓段面转成度。** 否决：这是一次横跨三个代码仓的破坏性变更，统一角度单位的决定必须对整个量纲系统一起下，而不是针对一个字段。
- **引入 `Degrees` / `Radians` 品牌类型，让传错单位在编译期失败。** 推迟，不是否决：这是正确的终态，文档中已把它标为理想做法，但它一次要碰所有带角度的签名，是独立的一次改动。
- **手工维护一张「哪些 cad op 能跑 brepkit」的表。** 否决：`engines` 本来就是唯一收窄轴，第二张清单是重复事实，会静默腐烂。文档给出的答案是既有的查询面——`describeLib('cad')` / `libsUnder(engineId)` 读的就是分派器强制的那份声明。

## Consequences

- 角度单位分野、句柄 `0` 规则、canonical 椭圆、只取闭合链的抽取规则各自有了一个权威归属，其余位置一律链接。
- 运行时什么都没改：没有改任何 op 签名、换算或错误。这些缺口是文档缺口，不是行为缺口。
- 宿主发射层在写草图文本之前有了一个指名可查的地方——这正是重点，因为这些缺口的代价一直是付在宿主侧的调试时间上。
