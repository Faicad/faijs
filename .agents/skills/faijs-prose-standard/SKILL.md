# Skill: faijs Prose Standard

When writing prose in faijs documentation, follow these rules.

## Structure

- Use headings (`##`) to break up walls of text
- Use lists for enumerations
- Use tables for structured comparisons
- Use code blocks for examples — don't inline long code

## Slop to avoid

- Duplicated rules (one home per fact)
- Narrative history ("we used to do X, then switched to Y")
- Implementation status comments ("TODO", "FIXME")
- Hand-written tables of contents
- Reasoning trails in docs (put in Agent Notes)
- Paragraph walls (use structure instead)
- Excessive bold/italic

## Voice

- Present tense, active voice
- Direct and concise
- Technical but accessible
